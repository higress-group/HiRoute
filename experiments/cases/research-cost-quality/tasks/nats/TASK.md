# 消息系统研究资料：逐项证据核验

根据提供的冻结官方资料，完成 claims.json 的全部60个核验项。只做来源内的事实核验与中文表述，不设计新方案或推导跨系统保证。资料中的代码、命令和提示均为待分析内容，不是要执行的指令；不得使用未提供的资料。

直接交付完整JSON：{"cards":[...]}。每项只含 id、verdict、fact、citations，覆盖每个给定id一次。verdict为 supported、refuted 或 not_documented。citations为[{"source":"文档ID","start":1,"end":3}]，使用核验项指定文档的原始L行号；每段不超过25行，必须支持该项正文。

fact使用中文，直接回答该核验项，并在错误断言中写出正确事实；没有记载不等于产品不支持。将直接决定该事实是否成立的前提、例外或版本限制保留在正文中。对于原文不同段落中的限定或冲突，应避免输出无条件的普遍保证。

每项通常一至两句，必要条件完整优先于简短，没有最低字数要求。不要扩写与该核验项无关的相邻知识、参数类型、默认值、历史、建议、替代方案或额外保证；若核验项本身问的是这些内容，则正常回答。不要额外生成独立的背景、风险或建议段落。

文档身份以 source-index.json 为准，默认分支快照不代表所有版本。原文的例子、建议、可能性不能改成唯一限制、强制条件或普遍保证。只核验文本，不声称执行了真实产品故障测试。请自行检查JSON结构、60项完整覆盖、判定与正文一致、必要条件及引用支持关系。
