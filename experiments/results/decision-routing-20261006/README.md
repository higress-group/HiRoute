# 决策路由实验结果（2026-10-06）

整理日期：2026-10-07。登记实验、独立文章盲评及本机 Desktop 观测核对已结束；没有为改善结果重跑样本。本页是实验记录，不是已经发布的宣传文章。

这轮写作任务中，全程 GLM 的四篇终稿达到预设编辑门槛；Qwen 写稿、GLM 审稿的组合没有显示质量增益。智能省钱的完整样本通过全部功能检查，但一直使用 Flash，没有发生自然升级。中途的执行器限制、产品修复、重启与决策超时使这轮实验不能作为严格的模型排行榜或节省比例证明。

## 实验与资源规则

- [智能省钱协议](../../cases/usage-reconciliation/README.md)：固定 Flash、固定 Max、Flash → Max 智能省钱，各两次独立会话；六轮逐步增加数据核对工具的要求。
- [写稿／审稿协议](../../cases/writer-reviewer/README.md)：全 Qwen、全 GLM、混合分工，分别比较中间档和最高档，每组两次；固定写稿 → 初审 → 修订 → 终审四轮。
- 业务模型均来自百炼 Token Plan；本轮路由决策使用 OpenRouter `typesafe/jev-1.13`。决策服务的其他 provider 验收不属于本轮模型比较。
- 两个执行 agent 按用户要求使用 `gpt-6.1-sol/max`。主线程通过真实 Desktop 配置、处理产品问题，并完成文章盲评与界面核对。
- 当前无实验 Token、单轮、整组或整体时长上限，默认上下文为 **272,000 tokens**。客户端默认 95% 的有效余量不等于另设小窗口。[资源修订](../../cases/user-resource-settings-20261006.md)优先于原始协议和较早的执行记录。
- 720 秒限制移除后，QM-2 修订轮自然运行 **1,090.896 秒**完成，终审运行 **352.891 秒**完成。旧的中断结果保持原状；没有回放或追加编辑轮次。
- 原先配置的 Jev 10 秒决策超时、单次 HTTP 请求 3,600 秒等待，与被移除的实验整轮限制是不同层次；没有设置新的替代整轮上限。

### 实际分工与计划不完全相同

XH-1 和 XH-2 的初审入口各发生一次 Jev 决策超时，按预设回退到 Writing；随后工具请求继承分支。因此两次初审分别有 6、9 个请求实际使用 **Qwen xhigh**，没有由 GLM 执行。这不是 15 次独立超时。两组终审实际使用 GLM max。

QM-2 修订入口也有一次决策超时，17 个请求沿用默认 Writing；该分支恰好与任务计划一致，模型仍为 Qwen medium。其余登记阶段未记录分支／模型偏离。写作共 361 个真实请求，均记录 HTTP 200，355 个执行完成、6 个取消；原生推理档位序列化违规为零。参数记录只能证明实际发送配置，不能证明供应商内部采用了相等的计算量。

### 审稿究竟改善了什么

初审 117 条意见中，独立诊断认为 77 条有效、15 条缺乏依据、25 条属于文风偏好；终审 36 条分别为 11、7、18。初审意见 94 条被接受、19 条部分接受、3 条未接受、1 条不适用。意见数、采纳率和审稿人自己的“可以发布”结论都不是文章质量分。

| GM-1 | 删除类似亲临现场的第一人称叙述；收窄无材料支持的因果判断 | 事实项由 2 到 4，总分增加 15，并跨过门槛 |

### 与人类原文比较，以及材料包的局限

对照为 Jordana Cepelewicz 的 [Quanta 原文](https://www.quantamagazine.org/is-ai-the-end-of-math-as-we-know-it-20261005/)。我的判断是：原文的现场与人物声音形成叙事推进，问题会随论述深化；这批 AI 稿更像结构清楚的材料综述，常反复使用“证明与理解”的比喻和并列建议。较好的 GLM 稿来源边界更稳，但人物质感与论证变化仍较弱。人类作者拥有采访、更长篇幅和编辑过程，不能据此计算公平的人机胜率，也不应鼓励模型编造现场来弥补差距。

揭盲后的原始来源复核发现一个重要材料遗漏：OpenAI 公告声称有外力的结果对应千禧难题 C/D 表述，而无外力 A/B 未解决；Clay 的题目确实列出这四种表述。因此，“有外力不等于无外力”不能推出“没有涉及千禧难题”。材料包保留了前一边界，却没有交代 C/D。少数稿件由此作出的更强否定不能作为可靠科普结论。[OpenAI 公告](https://openai.com/index/navier-stokes-solution/)、[Clay 原始题目](https://www.claymath.org/wp-content/uploads/2022/06/navierstokes.pdf)

这是评分冻结后的补充事实检查，**没有悄悄修改原材料、盲分或重跑文章**。原始公告是公司主张，不等于本实验独立证明其结果。这轮评分主要支持“相同闭合材料条件下的写作与审稿表现”结论，不能把高分稿视为已完成外部事实核查、可直接发布的新闻稿。

S-1 和 F-2 均逐阶段通过全部断言。M-1/M-2 的最终产物通过，但未满足六轮都正常完成的整段交付条件。F-1 第三轮的 7/9 是违规后的诊断结果，不计主比较。S-2 第 2–6 轮被旧执行器调用后均在本地被拒绝，没有新请求抵达模型。

S-1 的 111 个请求都走省钱分支。五次胜任评分为 0.835、0.870、0.885、0.835、0.765，均高于 0.5，但历史证据都标记为部分记录；它们评估此前累积阶段，不能与独立断言成绩互相替代。S-2 仅有 4 个真实 Flash 请求，无保存的胜任评分。两次 S 样本都没有 Max 请求。

全部登记执行及保留诊断共有 478 个真实请求，473 个记录能关联到 xhigh 参数、HTTP 200 与语义完成，其余 5 个关联不完整；没有推理档位参数违规。本轮说明 Flash 可以完成该任务、真实请求可被路由与追踪；**没有验证自然升级后能否恢复任务，也不足以建立“智能省钱比固定模型省多少钱”的因果结论**。两次完整 Flash 路径消耗不同，不能把随机执行差异归因于升级策略。

## 产品问题、修复与真实界面核对

过程中发现并修复了三类问题，详细过程见[观测修复记录](../../cases/observation-repair-20261006.md)：

1. 大量历史内容下的索引／查询工作过大，以及标题预览把完整性标记覆盖；读取路径现按有界工作推进，并保留内容缺失事实。
2. Responses 原生工具历史中的空名称导致后续对话被拒绝；修复只接受合法调用 ID 下的原生失败历史，不放宽工具定义与跨协议要求。
3. 流式正文捕获累积保留已处理数据的内存额度，历史突发又可能填满队列；修复复用现有预算树计量在用状态，并扩大有界队列，溢出仍显式记录。

最后部署的产品版本为 `d704c03ffb72f84a221746c4e6c10cfb1f7e4abb`。其精确候选完成 Gateway 435 项测试、观测 7 项与协议 41 项 E2E、相关 Clippy、macOS Desktop/daemon/CLI 编译及真实启动；另有 1 项既存外部凭证用例忽略，不算通过。回归在旧候选上先复现失败，再在修复后通过。未测试 Windows。最慢三个模块已记录评估，本次无证据支持另做性能重构。

QM-2 第一轮仍被旧 720 秒限制终止，其 20 个请求中 19 个完成、末个取消；留有对应中断记录，不能说整个会话完全捕获。原始运行目录丢失后，配置和后续运行都改放 HOME 持久目录；旧观测库无法恢复的会话只使用之前保存的回执。XH-2 修复部署时的进程重启也形成新的阶段编号区间，不能把显示的编号直接当成跨进程连续的实验轮次。

完整捕获的 QM-2 修订阶段获得 0.935 胜任度，但文章盲评只有 65 分，说明**路由胜任度不是经过校准的出版质量分**。本轮不应因此临时调阈值或改评分提示词；后续改进应作为新实验登记。
