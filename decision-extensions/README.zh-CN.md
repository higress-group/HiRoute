# 决策模型与路由机制

[English](README.md) · [自定义扩展 API](api/README.zh-CN.md) · [官方 Jev 扩展](extensions/jev-decider/README.zh-CN.md)

HiRoute 使用决策模型为当前任务选择执行模型，并在证据充分时评价上一实际执行阶段。你配置任务条件和模型组，HiRoute 在每条新用户消息到达时应用这些设置。

## 接入决策模型

1. 打开**模型 → 决策模型**，添加连接。内置接入支持**百炼**、**OpenRouter Jev**、**TypeSafe**及兼容 System One 端点。
2. 填写供应商、模型、完整接入点与凭证，保存并测试连接。
3. 在路由计划中选择已保存的连接，配置智能省钱或自定义任务分支及其执行模型。
4. 发布计划使配置生效。编辑连接或草稿后，需要在计划中选择对应版本并重新发布。

使用内置决策模型无需自行部署服务。连接测试使用合成输入检查已保存版本的传输和必要响应字段，不代表它对实际任务的判断准确率。

**自定义扩展**是可选的 HTTP 服务，自己对接供应商，并按 HiRoute 传入的任务定义和评分标准完成判断。在同一页面配置它的完整接入点即可；表单提供可复制请求和 OpenAPI 下载。[官方 Jev 扩展](extensions/jev-decider/README.zh-CN.md)是可部署的参考实现。

## 选择路由模式

| 模式 | 决策模型判断什么 | 执行模型 |
| --- | --- | --- |
| 智能省钱 | 当前任务是简单还是复杂 | 省钱组、主力组 |
| 自定义分支 | 当前任务属于哪类；有两组模型时再判断类内程度 | 每类常规模型，可选主力模型 |

任务类别、处理程度和胜任度回答三个不同问题：

| 问题 | 例子 | 作用 |
| --- | --- | --- |
| 当前做什么？ | 写稿或审稿 | 选择一个任务分支 |
| 这项工作需要什么程度？ | 局部措辞修改或全篇论证核查 | 在该分支内选择模型组 |
| 上一阶段做得如何？ | 稿件结构可用，但有未经证实的论断 | 记录胜任情况，适用时保护性使用主力模型 |

自定义条件重叠时按当前请求的主要意图选择；没有匹配时使用配置的默认分支。只有常规模型的类别不判断程度，但仍可记录胜任度。智能省钱只有一个任务范围，不把简单和复杂建成两个任务分支。

## HiRoute 如何选择和执行模型

有两组模型时，本次简单概率达到阈值（默认 **0.8**），且没有本次适用的完整低分，才选择常规或省钱组；否则选择主力组。胜任下限默认 **0.5**。低分保护只接受上一实际阶段的本次新评分，且要求类别、已发布计划版本和评分标准一致。缺失或部分证据保持未评分，不能视为零分；已保存的旧评分不会在后续轮次反复作为新低分。写稿评分不能使审稿任务升级。

每条新用户消息都重新决策，可能选择常规，也可能选择主力。工具续接和同轮重放只有在 HiRoute 可识别为同轮且冻结决策可复用时，才继承该决策；历史重建不连续或决策无法继承时仍会重新判断。“优先保持当前模型”只在新选中的组内合格候选中生效。

HiRoute 按顺序尝试选中组的候选。常规或省钱组耗尽后，可以接力同类别的主力组；主力组耗尽即失败。直接选择主力时只在该组内接力；单组类别在本组耗尽后失败。候选不可用不会生成胜任度评分。

类别有效但程度结果不可用时，HiRoute 使用该类别的主力组。整体决策失败时，智能省钱使用启发式规则；自定义分支使用默认类别，有主力组则优先使用主力。

## 调整判断设置和查看结果

高级判断设置默认收起。展开后可编辑简单/复杂条件、阈值、胜任评分要求，以及 **0 / 0.5 / 1** 三个评分锚点。类别条件描述任务意图，程度条件描述该类别内的工作要求，胜任标准评价已经发生的工作。

自定义类别默认跟随计划判断设置。“单独调整”复制完整设置，之后独立生效；“恢复计划默认”重新跟随计划。智能省钱还可显式选择启发式规则，规则不会产生模型胜任评分。

发布后，任务定义、连接版本和评分标准被冻结。会话与计划视图展示本轮为什么选择这个组、实际由哪个组和模型执行，以及该阶段后来获得的评分。后续评分和草稿修改不能改写过去的选择原因。

## 内置接入与自定义扩展的职责

| 职责 | 负责方 |
| --- | --- |
| 任务定义、胜任标准、阈值与模型组 | HiRoute，使用已发布计划 |
| 模型选择、资格检查、可用性接力与实际阶段观测 | HiRoute |
| 内置连接的 System One 供应商调用和答案映射 | HiRoute 的[内置适配器](api/system-one-design.md) |
| 自定义连接的供应商调用、答案映射和必要历史裁剪 | 自定义扩展，遵守传入的定义和标准 |

[自定义扩展 API](api/README.zh-CN.md)可在一次调用中返回当前决策和上一阶段评分。当前 **v1** 只有一种请求结构，[规范示例](api/decision-examples.json)和 [OpenAPI](api/decision.openapi.json)描述这一边界。完整当前输入保持不变，评分目标的证据缺失必须标记为部分证据。具体配置方式见[路由指南](../docs/smart-saving-model-classification.zh-CN.md)。

工具精选仅保留未来协议设计，目前没有运行时支持或产品入口。
