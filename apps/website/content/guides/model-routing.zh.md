# 使用智能模型路由

智能模型路由按已发布配置选择并执行模型。固定模型和免费优先按候选顺序工作；智能省钱和自定义分支通过判断选择模型组，并在每条新用户消息到来时重新判断。对于这两类需要判断的路由，能够识别为同一轮、历史连续且原选择可复用的工具续接沿用冻结决策，让 Agent 连续完成这一轮工作。

下面以桌面应用说明配置。Linux 无界面版通过相同的生产路径提供 `routing options/list/show/preview/apply` 和 `decision services list/apply/test`；先阅读 [Linux 无界面版安装](/docs/install-linux/) 和 [HiRoute CLI](/docs/cli/)，请求字段以当前安装返回的 schema 为准。第一次接入可按 [快速开始](/docs/) 创建固定模型路由，随后再配置决策模型。

## 选择路由类型

在“智能路由”中创建或编辑一份计划，在“怎样使用模型”中选择：

| 类型 | 适合什么情况 | 行为 |
| --- | --- | --- |
| 固定模型 | 需要可预测的候选顺序 | 按顺序尝试候选，跳过能力不满足或暂时不可用的模型 |
| 智能省钱 | 希望简单任务省钱，复杂任务使用主力 | 根据本轮程度判断及适用的上一阶段评分，选择省钱或主力模型组 |
| 自定义分支 | 写稿、审稿等任务需要不同模型 | 先选择任务类别，再在该分支内选择常规或主力模型组 |
| 免费优先 | 希望优先使用免费模型 | 按固定顺序尝试免费候选，可选择停止或进入主力兜底 |

“模型 → 通用模型”管理实际执行任务的模型。“模型 → 决策模型”管理用于判断和评分的模型连接，以及自行部署的自定义扩展。决策模型不会代替执行模型回答任务；本期也不支持工具精选。

## 连接决策模型

1. 打开“模型 → 决策模型”，选择“添加决策模型”。
2. 选择供应商，支持百炼、OpenRouter Jev、TypeSafe 及其他兼容接入。
3. 填写 API Key 和连接名称，确认模型名称与完整决策接入点。已有预填可展开修改，未预填则直接填写。
4. 选择“保存并测试”，或先“仅保存”，再在详情中选择“测试连接”。

内置决策模型由 HiRoute 提供判断和评分逻辑，不需要另外部署 Jev 服务。

![决策模型接入](/decision-assets/decision-models-zh-CN.png)

“保存并测试”先保存，再测试刚保存的准确连接版本。测试发送固定合成输入，可能消耗供应商额度，不读取真实会话，不执行任务，也不生成质量评分。通过仅说明该版本在这次测试中的连接和必要响应字段可用，不保证任务判断准确或持续健康。测试失败时配置仍可能已保存，按详情中的状态处理。

每次编辑保存都产生一个新版本。路由固定选中的连接版本；例如保存 r2 后，已发布路由仍使用 r1，直到你在路由中选择 r2 并发布更改。仅保存连接或测试连接不会发布路由。从未完成的路由中新增连接，会保留原草稿，返回后仍需主动发布。

需要自己实现判断和评分时，可在新增菜单中选择“接入自定义扩展”，填写完整接入点并选择认证方式。扩展遵守 [自定义扩展 API](/docs/decision-api/)；内置供应商配置和接口映射见 [决策模型接入指南](/docs/decision-extensions/)。可选的 [Jev 自托管参考扩展](/docs/jev-decider/) 提供自行部署的示例。

实际路由判断会把完整当前用户内容及允许的执行历史发送给所选决策连接。历史包括用户内容、已接受的回答、工具名称与顺序、显式粗粒度结果；请求正文不包含系统或开发者提示词、工具参数、工具结果正文和执行模型凭据。上一阶段评价使用该阶段执行时冻结的评分标准；可见历史和评分目标的不完整状态分别保留标记。

## 配置智能省钱

1. 选择“智能省钱”。“判断方式”默认使用决策模型，选择刚保存的连接版本；也可主动选择“启发式规则”或“自定义扩展”。
2. 在“省钱模型”中加入处理要求明确、范围有限任务的模型。
3. 在“主力模型”中加入处理复杂任务或保护低胜任阶段的模型。
4. 每组用“添加模型”逐个加入候选，调整上下顺序；需要时打开模型的思考设置，应用或取消修改。

![智能省钱配置](/decision-assets/config-zh-CN.png)

首屏只需选择判断方式及两组模型。“判断设置”默认收起，简单概率阈值默认为 **0.8**，胜任度下限默认为 **0.5**。展开后可分别修改简单/复杂的判断要求，以及“如何判断胜任”的评分要求和 0 / 0.5 / 1 三个评分标准。提高简单概率阈值会更谨慎地使用省钱模型；上一阶段的适用完整评分低于胜任下限时，本轮使用主力。

简单概率表达本轮任务的程度判断，不是执行模型回答正确的概率。

启发式规则只根据任务特征判断简单或复杂，不产生模型胜任评分，因此不显示概率阈值或评分提示词。切换判断方式再返回，会保留原来的连接及判断设置草稿。

## 配置自定义分支

选择“自定义分支”，例如分别为写稿和审稿安排模型。默认提供两个分支，可以按需添加：

1. 给每个分支填写名称和“任务条件”，如“根据资料起草或改写文章”“审阅现有文章并提出修改意见”。条件描述任务类别；简单和复杂的标准在“判断设置”中填写。
2. 加入“常规模型”。需要两档时，选择“添加主力模型（可选）”并加入候选。只配常规组的分支不判断程度，仍可记录胜任度用于观察。
3. 在计划底部展开“计划默认判断设置”，配置共用的阈值、程度条件与评分标准。
4. 分支默认跟随计划。需要不同标准时，展开该分支的“判断设置”并选择“单独调整”；要重新跟随计划，选择“恢复计划默认”。

![自定义分支配置](/decision-assets/custom-branches-zh-CN.png)

“单独调整”复制当前完整有效设置，此后整套独立，包括阈值、程度提示词与胜任标准。“恢复计划默认”清除整套覆盖，立即重新跟随计划，保留分支名称、任务条件和模型。没有主力的分支只展示胜任设置；添加主力后才出现程度设置。

每次只选择一个任务分支。条件重叠时按当前主要意图选择；均不匹配时使用“追问偏好与失败处理”中的默认分支，继续使用该分支的程度判断。写稿低分仍属于写稿阶段，不能因为本轮改为审稿就触发审稿主力。

## 理解本轮选择与失败处理

在智能省钱和自定义分支中，对于有两组模型的任务，只有本轮简单概率达到阈值、且没有适用低分时，才使用常规或省钱组；否则使用主力。默认值下，简单概率 **0.8** 达标，胜任度 **0.5** 达标，低于 **0.5** 才触发保护。

保护评分必须是本次决策新返回的完整有效评分，绑定上一真实执行阶段，且与本轮任务类别、发布配置和评分标准兼容。缺失、部分证据、跨分支或无法归属的评分不能触发保护；未评分不等于零，旧低分也不会反复生效。

新用户轮次重新选择，升级后的模型不会锁住后续轮次。本轮仍需按程度和适用评分判断，不会无条件重置为省钱组。“优先保持当前模型”只在本轮选中的模型组内生效。工具续接和重放在能够识别为同一轮、历史连续且冻结决策可复用时继承选择，不重复判断；上下文压缩或历史重建导致消息不连续、原决策无法复用时，会重新判断。

组内候选顺序用于故障接力。常规或省钱组耗尽后，继续同一任务分支的主力组；主力组耗尽后明确失败。直接选中主力时只尝试主力候选，不降回常规或跨任务分支；单组分支在本组耗尽后失败。候选调用失败不等于不胜任，不会因此生成零分。

若双组分支的任务类别有效但程度结果不可用，使用该分支主力并记录程度判断失败。整体决策失败时，智能省钱使用启发式规则，自定义分支使用默认分支的主力组（只有一组则使用常规组）。

所有候选都必须满足请求所需的文本、图片、工具和上下文能力。开始向客户端交付回答后，HiRoute 不会在同一回答中透明换模。

## 发布并连接 Agent

选择“启用”或“发布更改”，冻结连接版本、任务条件、判断设置、模型顺序及思考配置。无模型、缺连接或非法判断设置会阻止发布；隐藏在收起区域中的问题会展开定位。

随后在“Agent”页面选择目标 Agent，打开“模型路由”，启用 HiRoute 模型路由，勾选这份计划并选择默认项。保存后，按页面的真实检查或提交一个小任务，验证模型入口。

计划中的“单次请求最长等待”包含请求内重试和流式输出，新计划默认为 1 小时。慢速长回复到达该时限会被中断；请求写入、等待首包和响应流空闲阶段各默认为 10 分钟。可在路由中修改总等待时间，已有计划保留原值。这不改变模型自身的最大输出长度。

## 查看实际效果

在路由的“模型表现”中，按实际任务分支、模型组、模型及思考设置查看阶段样本和胜任度覆盖。智能省钱按“省钱 / 主力”分组；自定义分支按“写稿 → 常规 / 主力”等实际位置分组。同一模型用于不同组时分别记录。

会话的“模型表现”提供同一批阶段事实，可查看每个阶段的实际模型、胜任度和评分覆盖范围。

![会话阶段评分](/decision-assets/quality-native-zh-CN.png)

打开阶段的“查看评分依据”或“阶段详情”，再定位会话证据，依次核对：

- **本轮选择**：任务类别、简单概率、当时阈值、选中组及选择原因；没有程度判断时不适用，失败时不可用，都不能读作零概率。
- **实际执行**：真正调用的模型、思考配置、组内候选位置，以及发生的故障接力。
- **后续评价**：后一次决策对这个已执行阶段的评分、当时标准、评分覆盖与完整性；适用低分保护会指向它实际评价的旧阶段。

新草稿不能改写历史选择或阈值。未评分和部分证据应连同覆盖范围理解，HiRoute 不会根据一次低分自动改写计划。
