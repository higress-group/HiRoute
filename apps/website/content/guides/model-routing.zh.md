# 使用智能模型路由

智能模型路由让 Agent 使用你配置的一组模型。固定模型和免费优先按候选顺序尝试；智能省钱根据任务复杂度选择省钱或主力模型，自定义分支还会先区分写稿、审稿等任务类别。修改配置后，需要发布才能处理新请求。

智能省钱和自定义分支会在每条新用户消息到来时重新判断。同一轮内，Agent 调用工具后继续工作时，通常沿用本轮已经选定的模型组；具体条件见下文“理解本轮选择与失败处理”。

下面以桌面应用说明配置。Linux 无界面版可通过 CLI 的 `routing options/list/show/preview/apply` 和 `decision services list/apply/test` 配置相同功能，具体步骤见 [Linux 无界面版安装](/docs/install-linux/) 和 [HiRoute CLI](/docs/cli/)。请求字段以当前安装返回的 schema（请求和响应的结构说明）为准。第一次接入可按 [快速开始](/docs/) 创建固定模型路由，随后再配置决策模型。

## 选择路由类型

在“智能路由”中创建或编辑一份计划，在“怎样使用模型”中选择：

| 类型 | 适合什么情况 | 行为 |
| --- | --- | --- |
| 固定模型 | 需要可预测的候选顺序 | 按顺序尝试候选，跳过能力不满足或暂时不可用的模型 |
| 智能省钱 | 希望简单任务省钱，复杂任务使用主力 | 根据本轮复杂度判断及适用的上一阶段评分，选择省钱或主力模型组 |
| 自定义分支 | 写稿、审稿等任务需要不同模型 | 先选择任务类别，再在该分支内选择常规或主力模型组 |
| 免费优先 | 希望优先使用免费模型 | 按固定顺序尝试免费候选，可选择停止或进入主力兜底 |

“模型 → 通用模型”管理实际执行任务的模型。“模型 → 决策模型”管理用于判断和评分的模型连接，以及自行部署的自定义扩展。决策模型负责判断和评分，通用模型负责回答用户、调用工具和完成任务。

## 连接决策模型

1. 打开“模型 → 决策模型”，选择“添加决策模型”。
2. 选择供应商，支持百炼、OpenRouter Jev、TypeSafe 及其他兼容接入。
3. 填写 API Key 和连接名称，确认模型名称与完整决策接入点。已有预填可展开修改，未预填则直接填写。
4. 选择“保存并测试”，或先“仅保存”，再在详情中选择“测试连接”。

使用内置接入时，HiRoute 直接把判断问题发送给供应商的决策模型，并将结果用于路由。你不需要另外部署 Jev 服务。

![决策模型接入](/decision-assets/decision-models-zh-CN.png)

“保存并测试”会先保存连接，再用固定示例检查它能否返回符合要求的结果。测试可能消耗供应商额度，但不会读取你的真实会话。测试通过表示这次连接可用，实际判断效果仍需通过任务观察。测试失败不代表保存失败，请查看详情中的状态后修改或重试测试。

每次编辑保存都产生一个新版本。已发布路由继续使用原来选定的版本；例如连接从 r1 更新为 r2 后，需要在路由中选择 r2 并发布更改才会切换。仅保存连接或测试连接不会发布路由。从未完成的路由中新增连接，会保留原草稿，返回后仍需主动发布。

需要自己实现判断和评分时，可在新增菜单中选择“接入自定义扩展”，填写完整 endpoint（请求地址）并选择认证方式。扩展遵守 [自定义扩展 API](/docs/decision-api/)；内置供应商配置和接口映射见 [决策模型接入指南](/docs/decision-extensions/)。可选的 [Jev 自托管参考扩展](/docs/jev-decider/) 提供自行部署的示例。

实际路由判断会把当前用户的完整输入和保留的执行历史发送给所选决策服务。历史包含用户内容、已接收的模型回答、工具名称、执行顺序，以及协议明确报告的工具状态；不包含系统或开发者提示词、工具参数、工具结果正文和执行模型凭据。上一阶段按执行时保存的标准评分，缺少的历史证据也会标记出来。

## 配置智能省钱

1. 选择“智能省钱”。“判断方式”默认使用决策模型，选择刚保存的连接版本；也可主动选择“启发式规则”或“自定义扩展”。
2. 在“省钱模型”中加入处理要求明确、范围有限任务的模型。
3. 在“主力模型”中加入处理复杂任务、或在上一阶段表现不佳时接手的模型。
4. 每组用“添加模型”逐个加入候选，调整上下顺序；需要时打开模型的思考设置，应用或取消修改。

![智能省钱配置](/decision-assets/config-zh-CN.png)

首屏只需选择判断方式及两组模型。“判断设置”默认收起，简单概率阈值默认为 **0.8**，胜任度下限默认为 **0.5**。展开后可分别修改简单/复杂的判断要求，以及“如何判断胜任”的评分要求和 0 / 0.5 / 1 三个评分标准。提高简单概率阈值会更谨慎地使用省钱模型；如果上一阶段的完整评分适用于本轮任务、且低于胜任度下限，本轮会使用主力模型。

简单概率表示决策模型认为当前任务符合“简单”条件的可能性。例如返回 0.9，表示它更倾向于判为简单，并不表示执行模型有 90% 的成功率。

启发式规则只根据任务特征判断简单或复杂，不产生模型胜任评分，因此不显示概率阈值或评分提示词。切换判断方式再返回，会保留原来的连接及判断设置草稿。

## 配置自定义分支

选择“自定义分支”，例如分别为写稿和审稿安排模型。默认提供两个分支，可以按需添加：

1. 给每个分支填写名称和“任务条件”，如“根据资料起草或改写文章”“审阅现有文章并提出修改意见”。条件描述任务类别；简单和复杂的标准在“判断设置”中填写。
2. 加入“常规模型”。需要两档时，选择“添加主力模型（可选）”并加入候选。只配常规组的分支不判断复杂度，仍可记录胜任度用于观察。
3. 在计划底部展开“计划默认判断设置”，配置共用的阈值、复杂度条件与评分标准。
4. 分支默认跟随计划。需要不同标准时，展开该分支的“判断设置”并选择“单独调整”；要重新跟随计划，选择“恢复计划默认”。

![自定义分支配置](/decision-assets/custom-branches-zh-CN.png)

“单独调整”会复制计划当前的阈值、复杂度判断要求和胜任标准；之后修改计划默认设置，不再影响这个分支。“恢复计划默认”会移除这份独立设置，让分支重新跟随计划，同时保留它的名称、任务条件和模型。没有主力的分支只展示胜任设置；添加主力后才出现复杂度设置。

每次只选择一个任务分支。条件重叠时按当前主要意图选择；均不匹配时使用“追问偏好与失败处理”中的默认分支，继续使用该分支的复杂度判断。写稿低分仍属于写稿阶段，不能因为本轮改为审稿就触发审稿主力。

## 理解本轮选择与失败处理

在智能省钱和自定义分支中，对于有两组模型的任务，只有本轮简单概率达到阈值、且没有适用低分时，才使用常规或省钱组；否则使用主力。默认值下，简单概率 **0.8** 达标，胜任度 **0.5** 达标，低于 **0.5** 才触发保护。

用于低分保护的评分必须由本次决策返回，评价上一实际执行阶段，并有完整证据。上一阶段与本轮还必须使用相同任务类别、发布版本和评分标准。缺失、部分证据、跨分支或无法归属的评分不能触发保护；未评分不等于零，旧低分也不会反复生效。

每条新用户消息都会重新选择。上一轮使用主力，不代表以后都用主力；也不会一开始新轮次就自动回到省钱组。“优先保持当前模型”只在本轮选中的模型组内生效。工具续接和重放在能够识别为同一轮、历史连续且冻结决策可复用时继承选择，不重复判断；上下文压缩或历史重建导致消息不连续、原决策无法复用时，会重新判断。

组内模型按你设置的顺序尝试，这就是故障接力。常规或省钱组都无法使用时，再尝试同一任务分支的主力组；主力组也无法使用时，请求失败。直接选中主力时只尝试主力候选，不降回常规或跨任务分支；单组分支在本组耗尽后失败。候选调用失败不等于不胜任，不会因此生成零分。

若双组分支的任务类别有效但复杂度结果不可用，使用该分支主力并记录复杂度判断失败。整体决策失败时，智能省钱使用启发式规则，自定义分支使用默认分支的主力组（只有一组则使用常规组）。

所有候选都必须满足请求所需的文本、图片、工具和上下文能力。开始向客户端交付回答后，HiRoute 不会在同一回答中悄悄换用另一个模型。

## 发布并连接 Agent

选择“启用”或“发布更改”后，HiRoute 会保存本次生效的连接版本、任务条件、判断设置、模型顺序及思考配置。之后编辑草稿不会立即影响正在使用的配置。无模型、缺连接或非法判断设置会阻止发布；隐藏在收起区域中的问题会展开定位。

随后在“Agent”页面选择目标 Agent，打开“模型路由”，启用 HiRoute 模型路由，勾选这份计划并选择默认项。保存后，按页面的真实检查或提交一个小任务，验证模型入口。

计划中的“单次请求最长等待”包含请求内重试和流式输出，新计划默认为 1 小时。慢速长回复到达该时限会被中断；请求写入、等待首包和响应流空闲阶段各默认为 10 分钟。可在路由中修改总等待时间，已有计划保留原值。这不改变模型自身的最大输出长度。

## 查看实际效果

在路由的“模型表现”中，按实际任务分支、模型组、模型及思考设置查看阶段样本和胜任度覆盖。智能省钱按“省钱 / 主力”分组；自定义分支按“写稿 → 常规 / 主力”等实际位置分组。同一模型用于不同组时分别记录。

会话的“模型表现”展示同一批执行记录，可查看每个阶段的实际模型、胜任度和评分覆盖范围。

![会话阶段评分](/decision-assets/quality-native-zh-CN.png)

打开阶段的“查看评分依据”或“阶段详情”，再定位会话证据，依次核对：

- **本轮选择**：任务类别、简单概率、当时阈值、选中组及选择原因；没有复杂度判断时不适用，失败时不可用，都不能读作零概率。
- **实际执行**：真正调用的模型、思考配置、组内候选位置，以及发生的故障接力。
- **后续评价**：后一次决策对这个已执行阶段的评分、当时标准、评分覆盖与完整性；适用低分保护会指向它实际评价的旧阶段。

新草稿不能改写历史选择或阈值。未评分和部分证据应连同覆盖范围理解，HiRoute 不会根据一次低分自动改写计划。
