# 快速开始

先选择运行方式，接入模型来源，再创建一条路由并连接你的 Agent。想直接试一个新模型，可以从首页的“新模型”开始，按 [试用新模型](/docs/model-trial/) 一次完成选模型、发布路由和映射 Agent。按难度分流路由可以选择本地的启发式规则，不要求部署外部决策服务；任务委派是独立能力。

## 1. 选择运行方式

- **macOS 桌面应用**：要求 macOS 15.0 或更高版本。公开安装包为自签名构建，下载后先核对 SHA256，再按 [macOS 安装与首次启动](/docs/install-macos/) 的说明打开应用。
- **Windows 桌面应用**：使用原生 x64 安装包，按当前用户安装，自带服务与 CLI，不要求 Python 或管理员权限。参见 [Windows 桌面版安装](/docs/install-windows/)。
- **Linux Web UI 与 CLI**：面向服务器、远程工作站和自动化环境，支持 x86_64 与 ARM64，按当前用户安装，不需要 `sudo`。启用 Web UI 后，在浏览器打开登录链接即可使用与桌面版相同的界面，服务器无需安装桌面环境。参见 [Linux 安装](/docs/install-linux/)。

[下载页](/download/)列出已发布的安装包。

下面第 2–5 步适用于桌面应用与 Linux Web UI。浏览器管理的是服务所在主机的模型、路由、Agent 和文件，也可以用 CLI 完成配置。无论使用哪种入口，都先确认本机服务已经就绪；模型路由、会话记录和任务执行都依赖它。

## 使用 CLI 或 Agent 接入

运行 `hiroute quickstart` 查看当前服务、准确的配置目标和可复用来源/路由；选定后加 `--context CONTEXT_ID --plan PLAN_ID`。指定 Hermes 配置时可加 `--hermes-root /ABSOLUTE/EFFECTIVE/ROOT`。这个入口只读状态，并说明还缺哪些选择以及下一步命令。

主路径是“来源 → 路由 → 目标 Agent → 原生加载 → 匹配的真实请求证据”。现有 Preview 命令支持简化选择和 `--apply-file PATH`，无需手写完整编辑器或搬运摘要。参见 [CLI Quickstart](/docs/cli/)，了解直接按难度分流组合、调整、响应丢失后的恢复和独立能力恢复。同一管理 Skill 可在任何受支持 Agent 中运行并管理另一个目标，调用方自己的模型可以保持原生接入。

需要决策模型时，先用 `hiroute decision services options` 查看可复用连接和安装包预设。凭证由用户在自己的终端通过不回显提示录入，再让管理 Agent 继续保存、测试和绑定路由；不要把密钥发到聊天。具体步骤见 [CLI 决策模型接入](/docs/cli/)。

## 2. 连接一个模型

打开“模型 → 通用模型”，选择“添加模型”。可以连接订阅、扫描本机复用已有的订阅和模型配置，或新建 API 接入。通用模型负责实际执行任务；首次使用先完成这项连接即可。订阅和 API 一起接入、API Key 花费额度和代理设置见 [接入模型](/docs/models/)。

检查连接后，选择要加入 HiRoute 的模型并保存。页面上的“接入就绪”表示这项连接具备进入路由的必要资料，不等同于每个上游模型都已经完成一次真实推理测试。

## 3. 创建第一条智能路由

打开“智能路由”，选择“新建智能路由”：

1. 填写名称和使用场景，例如“日常开发”和“处理常规代码修改”。
2. 按需求选择“固定模型”并添加候选，或直接选择“按难度分流”，配置常规组、主力组和明确的决策方式。
3. 选择“启用”。只有已发布并启用的路由会处理新请求。

也可以在模型详情中选择“创建智能路由”，直接用这个模型创建一条固定模型路由。进一步的设置可按 [智能模型路由](/docs/model-routing/) 配置“按难度分流”“自定义分支”或“免费优先”。需要模型判断和阶段评分时，再到“模型 → 决策模型”添加内置连接，或接入自行部署的自定义扩展。

## 4. 连接你的 Agent

下面以 Codex 为例。打开“Agent”，选择已发现的 Codex，在“模型路由”中选择“启用”，然后：

1. 选择“接入方式”。推荐“按需使用 · 仅 CLI”：只影响 HiRoute 专用的 profile，普通 Codex 和 Desktop 保持原配置。“设为默认 · CLI 和 Desktop”会让共享同一配置目录的 Codex CLI 和 Desktop 都使用 HiRoute。
2. 在“Codex 可用模型”中勾选刚创建的智能路由，并在“默认选择”中把它设为默认。
3. 按需使用时选择“启用并复制启动命令”，在终端里用这条命令启动 Codex。设为默认时选择“启用模型路由”，保存后重新启动 Codex CLI 或 Desktop。

设为默认后，Codex 会按模型服务商筛选 `/resume`，原有会话可能不再显示，但会话文件仍然保留；页面的“查找原有会话”说明了找回方法。

其他 Agent 的接入方式：

- **Claude Code**：直接启动 `claude`，用 Opus、Sonnet、Haiku 原生预设选择映射的路由。
- **Qoder、Pi、DeepSeek Harness、OpenCode**：添加可以在模型选择中明确选用的 HiRoute 路由，原有模型和默认值保持不变。保存后重新启动 Agent，在模型选择中选用。
- **Hermes**：先选择本机 Hermes 实际使用的配置目录，再选一条路由作为默认主模型。

使用路由时请保持 HiRoute 运行；启用不会自动设置开机启动。HiRoute 会保留恢复点，若以后停用模型路由，可以在“连接详情与恢复”中恢复接入前的设置。

## 5. 发起一次真实请求

按提示加载原生配置并选择模型，再发起已授权、可明确验收的小任务。配置已保存不代表运行中的会话已经切换。请求开始后，在 HiRoute 的“会话”中查看路由时间线：实际路由、模型、用量和执行状态。
